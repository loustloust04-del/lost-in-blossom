## 背景

这个 App 是两个人一年多堆出来的，中间换过很多窗口、很多次"先能用再说"。兔兔自己的判断是「已经变成屎山了」。
现在需要一次体检，搞清楚**哪些地方真的该动**，而不是凭感觉重构。

## 你要找的东西（按优先级）

**P0 · 会咬人的**
- 同一份数据有两套真相：某个状态既存本地又存服务器、两边可能不一致（已知例子：进食/饮水曾用 max() 创可贴糊过）
- 静默失败：catch 了什么都不做、`try?` 吞掉错误、guard else return 之后没人知道发生了什么（已知教训：语音条卡了一周就是这个）
- 会崩的：数组越界、强解包、主线程上的重活、可能的死循环（已知教训：AttachmentStore 的 while 死循环冻死过主线程）

**P1 · 拖慢的**
- SwiftUI 里被反复重算的大块：body 内联太多、@Observable 订阅面过大、ForEach 吃整条数组
- 每次进页面都重新拉网络、没有缓存的地方（已接缓存的：留言板/心愿单/纪念日/药箱/经期/音乐；其余待查）
- 定时器、轮询、后台任务有没有跑空转的

**P2 · 屎山本身**
- 死代码：没有 call site 的函数/视图/文件（已知：`gateway/src/memory/` 下 15 个模块大半没在跑）
- 重复实现：同一件事有两三种写法（已知例子：曾有 vitals_meds 和 meds_take 两套记吃药）
- 超长文件该拆：CardFlowView 2491 行、SidebarView 1877、PersonaSettingsTab 1619、ConversationViewModel+Chat 1619
- 命名/口径不统一：Bunny vs 兔兔 vs 用户 vs 她；同一概念多个名字

## 怎么报告

写成 `docs/AUDIT-REPORT-<日期>.md`，每条包含：
1. **文件:行号**
2. **问题一句话**
3. **危害等级** P0/P1/P2
4. **建议怎么改**（一句话，不用写代码）
5. 如果只是"看着乱但没危害"，标注 **可不改**

**最重要的一条要求：按「值不值得动」排序，不要按「有多丑」排序。**
能跑了一年没出事的丑代码，优先级低于一个刚写的、看着漂亮但会静默失败的新函数。
