## 二、刀序（4 刀，每刀独立 commit）

### 刀1 · 提取降敏（prompt + 间隔化）

**a) 提取间隔化**：不再每轮都提取。`extractMemoriesIfNeeded` 加间隔守卫：
- 方案 A：**轮次计数**——每 N 轮提取一次（N=3？5？⧫ 批注点 1）。在 CV 加 `extractRoundCounter`，每轮 +1，满 N 才调提取，提取后清零。
- 方案 B：**时间间隔**——上次提取后 M 分钟内不再提取。比轮次更稳（长对话快聊 vs 慢聊），但需要多一个 `lastExtractedAt` 状态。
- ⧫ 你选 A 还是 B？间隔多少？我建议 **A, N=3**（每 3 轮提取一次，提取窗口 5 条覆盖这 3 轮 + 前 2 轮衔接）。

**b) 提取 prompt 降敏**：规则 8 改更狠 + 加规则 11：
- 规则 8 从"不存日常闲聊"扩展为：「不存：日常闲聊、一次性问题、用户在问（而非陈述）的信息、**已有记忆已覆盖的信息（哪怕措辞不同）、对话中的重复提及（同一轮说了两遍不算两个事实）**。宁可漏存也不重复。」
- 规则 11（新）：「当前记忆库已有 N 条以上时，add 门槛提高——只存**全新信息**（以前的记忆中完全没涉及的主题），不存已有主题的细化或换种说法。」
- ⧫ 批注点 2：规则 11 的 N 阈值多少？建议 50 条。还是你觉得不用做门槛分级？

### 刀2 · 做梦毕业制（碎片→画像后标 superseded）

`DreamConsolidator.dream` 成功返回新画像后：
1. 把参与聚合的 `facts` 的 id 传回调用方（现在只传纯值 `(content, category)`，加 `id: UUID`）。
2. 调用方拿到 id 列表，对每条执行 `store.supersede(id:)`——标记 `supersededAt = now`，退出排名但不删库。
3. **钉住记忆（isUserExplicit）不毕业**——用户手动创建的事实不因做梦被淹没。
4. 面板显示：已毕业的碎片灰条标"已凝入画像"（supersededAt 已有灰条，标签文案区分来源？⧫ 批注点 3：需要区分"被矛盾淘汰"和"已凝入画像"的原因吗？还是都叫"已失效"就行？如果要区分，Memory 加 `supersededReason: String?`——"contradicted" / "graduated"——可选轻量字段）。

### 刀3 · 衰减触发补全

现状 `applyDecay` **只在切换对话时触发**（`consolidateSessionMemories`）——聊 100 轮不切对话 = 衰减 0 次。补两个触发点：
1. **提取后触发**：`extractMemoriesIfNeeded` 调完提取后顺手 `applyDecay`（提取是后台 fire-and-forget，衰减一并完成，零额外时机）。
2. **做梦时触发**（可选）：做梦前先衰减一轮——让做梦看到的权重是真实的（冷记忆权重高假象会影响画像质量）。

效果：每 N 轮聊天至少衰减一次；冷记忆真的冷下去，hot 池瘦身，注入预算留给真正活跃的事实。

### 刀4 · 存量一键整理（设置页，⧫ 批注点 4）

手机上 189 条堆了的存量，靠流程改善只管增量。需要一个存量清洗入口：
- **设置-记忆**加「整理记忆」按钮：
  1. 全库向量查近似 pair（>0.75 阈值）→ 每对保新的 supersede 旧的
  2. 若有画像 → 把与画像内容近似的碎片标毕业（防双倍注入）
  3. 结果报告"合并 X 对 / 毕业 Y 条 / 剩余 Z 条"
- 要不要做这个一键按钮？还是你自己手动在面板里逐条清？
- ⧫ 批注点 4：做不做按钮？自动跑还是手动触发？

## 三、不退化保证

- 刀1 间隔化：首轮必提取（counter 初始=N），不会"前几轮什么都没记住"
- 刀2 毕业：钉住免疫；关 mem_supersede_soft 时毕业也不执行（开关统一守卫）
- 刀3 衰减：只是多加触发点，衰减逻辑本身不动（effectiveWeight / reinforce / 开关化全在）
- 刀4 存量：手动触发按钮（或设置入口），不自动跑，跑前二次确认

## 四、验收清单
