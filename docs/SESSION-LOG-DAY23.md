## 二、vitals 单一真相源改造（兔兔拍板「彻底解耦」）✅
起点是**主人的工单**（兔兔发现）：控制台把昨天和今天的饮食混在一起。层层剥出四真凶：
1. `today()` 用 **UTC 切日** → 她北京时间凌晨 0-8 点的宵夜被算进昨天（跨日判定偏 8h）
2. `load()` 发现日期变了**只在内存返回空数据、从不落盘** → 下一次 save 把旧 meals 写回
   （昨天小火腿和今天胡辣汤同框的直接原因）
3. 翻篇即丢，**没有归档**
4. 清完不到一小时又混回来 → **merge 接口不问日期**，App 侧缓存把归档过的旧饭灌回今天
修：北京日界 + archive() 按日归档（留 90 天）+ 翻篇立刻落盘 + GET /api/vitals/history；
merge 加日期闸 + 拒收归档过条目；控制台补**下拉刷新**（此前只在进页面拉一次）。
**终局（兔兔提议）**：饮水/进食**只有网关一个主人**——App 从不产生这些数据，本地
DailyContext 只是镜子。改为**只拉不推、服务端整份覆盖**，显示层去掉 max(本地,服务端)。
> 与群聊病灶同源：**状态没有真相源，靠现场推算和互相猜**。
