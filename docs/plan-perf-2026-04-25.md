## 二、推测原因（按嫌疑排序）

### 🎯 线 A — 一次切对话触发 4 次 ContentView.body

**#5（+9ms）和 #7（+932ms）这两次的触发源不明**。

候选触发源（待 grep 验证）：
- `viewModel.selectedConversation` 写入（onChange L338）
- `viewModel.currentPath = []` 之类的 reset
- `pendingScrollNodeId`、`scrollToNodeId`、`highlightedNodeId` 等中间 state
- `iOSPage` 切换（sidebar→chat 是 0→1）
- `currentPage` binding write-back（PagingViewController.onPageChanged async）
- 其他 @Observable property mutate

**影响**：每次 body × 3 棵 SwiftUI tree re-diff（PagingContainerView.updatePages 全量替换 listPage + chatPage + dashPage 的 AnyView）。即便 SwiftUI 跳过 unchanged subview，`AnyView(injectChatManagers(...))` 重 init + UIHostingController.rootView setter 自身有成本。

### 🎯 线 B — 第一次 buildTreeInBackground 445ms（nodes=1）

后续 warm 33-37ms。**第一次冷多花 408ms**，1 个 node 不该这么慢。

候选 cold cost：
- SwiftData 第一次 fetch（@Query / FetchDescriptor 第一次跑）
- nodeMap / effectiveChildrenMap 第一次构建
- Predicate 第一次 compile（`profileId == X` predicate cache miss）
- `currentPath` 后台 fetch 时主线程在等什么

**影响**：用户切第一个对话能感知到 ~半秒的"微卡"，之后顺。

### 🎯 线 C —（防御性）updateUIViewController 没 short-circuit

`PagingContainerView.updateUIViewController`（PagingContainerView.swift:74-95）每次 body 都：
1. 重建 3 个 AnyView 调 `vc.updatePages([...])`
2. 调 `vc.applyWallpaper(wallpaper)`（即便 config 不变）
3. 调 `vc.setScrollEnabled(...)` + `setShieldHiddenByCaller(...)`

**与线 A 互补**：即使无法把 body 数从 4 降到 1，下游 `updatePages` / `applyWallpaper` 可以加 guard 跳过 no-op。

### 已排除

- ✅ **H3 idle invalidate**：log 实证排除
- ✅ **第一次键盘 cold path**：log 实证不显著
- ✅ **GlassEffect / VariableBlur 数量**：本身存在但不解释 idle 0 body 现象（GPU 路径与 SwiftUI body 路径解耦；如果 17 Air 还感觉微卡，可能是 GPU 路径剩余影响，但优先级靠后）

#### 3.1 Postmortem — 为什么线 C 走不通

错把 SwiftUI conditional view 的语义想成 SwiftUI render 时再 evaluate condition。事实：

```swift
ZStack {
    if viewModel.selectedConversation != nil {
        CardFlowView
    } else {
        EmptyStateView
    }
}
```

ViewBuilder 编译成 `_ConditionalContent<CardFlowView, EmptyStateView>` 实例。**分支选择在 ContentView.body 执行那一刻 frozen 进 view tree 实例**，不是 SwiftUI render 时再 evaluate。

`iOSChatPage` 在 ContentView.body 执行时构造视图树，包成 `AnyView` 传 `vc.updatePages([...])`，`UIHostingController.rootView = AnyView`。

线 C skip `updatePages` → UIHostingController 永远 hold 第一次 AnyView（启动时 `selectedConv=nil` → `_ConditionalContent.falseBranch(EmptyStateView)`）。后续 ContentView.body re-eval 构造**新** AnyView（含 trueBranch CardFlowView），但**没传进去** → 用户看到永远 EmptyStateView。

**关键认识**：
- children view 内部自己的 @Observable 订阅只能 invalidate 它**自己的** view body，**propagate 不到父级 conditional 选择**
- AnyView 内部的 `_ConditionalContent` 一旦构造就 frozen，靠 children re-eval 改不了分支
- 只要 ContentView.body 内含任何 conditional view（`if/let-else/switch`），UIHostingController.rootView 就必须每次 ContentView.body re-eval 都更新
- 这条路要走通必须把 conditional 移进**单一稳定 view** 内（线 E）— 大重构，本轮不做

#### 5.2 `_logChanges()` vs `_printChanges()` 用法

`_logChanges()`（Hermes Q2 推荐 newer variant）：

```swift
struct ContentView: View {
    var body: some View {
        let _ = Self._logChanges()     // unified logging (os_log)
        ...
    }
}
```

输出去 Console.app 的 unified logging（subsystem 类似 `com.apple.SwiftUI`），不是 stdout — Xcode console 仍能看到，但 grep filter 跟 `[PERF]` print 不一样。

`_printChanges()` 老 variant：直接 print 到 stdout，跟 `[PERF]` 字段同流。

**先试 `_logChanges()`，build 不通过就退 `_printChanges()`**。两者都 underscore-prefixed 非 public API。

#### 5.3 风险评估

- ✅ 探针纯 DEBUG，Release 自动剥
- ✅ 不动业务代码
- ⚠ underscore API 可能 iOS 26 / Xcode 16 改变签名 — 用 #if compile guard 包
- ⚠ snapshot dict 字段加多了每次 body 多扫几个 manager 属性，但都是 O(1) 读取，对总开销可忽略
- ⚠ `colorScheme` 本身就是 ContentView body 内的 `@Environment(\.colorScheme)`，读它的探针等于 invalidate 它 — 不算坑，但要意识到 read 会订阅

### 经验教训写入项目记忆

值得记到 `~/.claude/.../memory/`：

1. **SwiftUI `_ConditionalContent` frozen at parent body construction**（B v3 regression 教训）：parent body 内 `if/else` 是 ViewBuilder 编译时定 branch，`AnyView` wrapping 不参与 SwiftUI 精细订阅。skip `UIHostingController.rootView` 替换 = 永不 swap branch。
2. **探针自身 observer effect**：snapshot 字段 read = view 订阅。生产代码不订阅的 source 不要 read 进 snapshot，否则 measurement 失真（c+d 教训）。
3. **`@AppStorage` 的 dead-on-platform 订阅**：跨平台 view 上的 `#if os(macOS)` only 字段，AppStorage declaration 仍让全平台 view 订阅 UserDefaults wrapper —— 启动后 sync 触发 ghost body。declaration 包 `#if os(macOS)` 才彻底切断（线 d 教训）。
4. **UIKit/CALayer setter 不保证 idempotent**（Hermes Q3 sourced）：alpha/transform/colors/bgColor 都没 doc 保证去重，hot path 上自己 guard 是合理优化。
5. **Hermes 5 条查询作为 perf research 验证工具的标准动作**：写 plan 前并行查 Apple docs / 社区共识，**不依赖经验臆测**。
