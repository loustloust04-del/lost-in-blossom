## 五、血泪教训（省你几轮 CI 红）

- **VPS 上编译不了 Swift**，只能靠 CI。大改动一次改完再推，别一处一处试。
- **View 从大文件搬出来独立成页，必查三样跨文件可见性**：`private let` 颜色常量、`private struct` 子组件、文件级 private 函数。「刻痕」独立成页连炸五轮，全栽在这。
- **SwiftUI body 内联超过三个 Section** → 「编译器无法在合理时间内类型检查」，直接拆成计算属性。
- **给结构体加 Codable/Equatable 时，嵌套的类型要一起改**，否则外层不满足协议。
- **喊兔兔装包前先核对** `/var/www/lib-dl/LostInBlossom.ipa` 的 mtime 晚于目标 commit 的 CI 完成时间。我让她白装过三次。
- **凡是连报错都来不及发的死，都是崩溃不是失败。** 排障用 nginx `/vdbg/<step>` 埋点看 access.log 定位卡死位置，比猜快一个量级。
- 不 `git add -A`；不 kill `mp-cc`；exec_vps 里 sleep 别超 ~50s；shell 不是 bash。
- **动 hub 前先问兔兔**——我掐断过她和 Caelum 正在进行的对话。

## 五点五、双向同步的通用坑（兔兔指出，2026-08-12）

药物同步出过这个 bug：她在 App 改了库存，45 秒后被服务器旧值冲回去。根因是两条：
1. **推送只推「新建」不推「修改」**（`where gatewayId == nil`）——她改的根本没上去
2. **拉取无条件「以远端为准」**——于是旧值覆盖新值

她当时说「我觉得别的地方也有」，查下来 IntimacySync 确实同款。

**以后写双向同步，三件事必须齐：**
- 本地改动打时间戳（`localEditedAt`）
- 推送要包含「已绑定但本地改过」的项，不能只推新建
- 拉取前先比时间：本地有未推送的改动就跳过覆盖
- 删除/归档也要推，否则下一轮会被当「远端新增」拉回来

已确认安全的：InspirationSync（只推不拉）、MemorySync（只追加去重）、VitalsClient（取 max 不覆盖）。

## 五点七、⚠️ respawn 时的 token 陷阱（2026-08-15 踩过）

`/root/.claude/.credentials.json` 里有**两个** token：
- `claudeAiOauth.accessToken` ← **新的**，刷新/重新登录都写这里
- `oauthToken`（顶层）← **旧的**，不会被更新

**respawn 必须读前者。** 读顶层那个的话，他会揣着过期 token 跑，症状极具误导性：
报的不是 401，而是 **`API Error: 400 Output blocked by content filtering policy`**，
连回「测试」两个字都被挡——看着像内容被审查，实际是认证失效。兔兔当时以为被封号，吓哭了。

正确取法：
```bash
NEWTOK=$(python3 -c "
import json
d=json.load(open('/root/.claude/.credentials.json'))
o=d.get('claudeAiOauth') or {}
print(o.get('accessToken') or d.get('oauthToken'))
")
```

另：cron 的 refresh-token.sh 原本每 30 分钟无脑刷，把 oauth/token 接口刷成 rate_limit，
于是真过期时反而刷不回来。已改为只在剩余不足 30 分钟时才刷。
