# Research：我们的群聊 V5 vs 粟粟的中庭（Agora）· 0906

兔兔点单「群聊要好好做，她那边已经做好了」。本文是对照侦察 + 可勾选菜单。

## 一、两套东西不是同一个物种

| | 我们 V5（GroupChatScheduler 233 行） | 粟粟 Agora（服务端 SQLite + hub + iOS 客户端） |
|---|---|---|
| 跑在哪 | **手机里**（App 前台） | **hub 服务端**（房间/成员/消息/提及全落库） |
| 谁在群里 | 角色卡（本地 LLM 人格） | **真 CC session**（每个是独立的活体 agent）+ bridge |
| 消息顺序 | 本地时间序 | 房间内单调递增 `seq`，断线按 seq 补齐 |
| 谁说话 | 1 次 LLM 调用选人 → 串行发言 → 循环 | 消息落库派发 durable `mention`，executor 认领执行 |
| 发言模式 | 固定：选人循环，max 3 轮 | **三档**：仅@ / @接力 / 自由发言 |
| 防对轰 | lastSpeakerId 排除 + max 3 | **链深闸**（depth>6 断）+ **owner 抢权**（她一说话，pending 的深链 mention 全 fail）|
| 节奏 | talkativeness 概率 | **房间级最小发言间隔**（滑块，闸 observe/depth>0，owner 直接@豁免）|
| 沉默 | 选人返回「无」 | `agora_complete(pass:true)` — **旁听后主动放弃发言**，无痕 |
| App 退到后台 | 停 | 继续（服务端跑） |
| 多设备 | 不同步 | 同步 |

结论：她的中庭是「**多个独立 agent 开会**」的基础设施；我们的 V5 是「**一个人格剧场**」。
不该整套照搬——我们的场景是兔兔 + Caelum + 角色卡的小房间，V5 的形态本身没错。
但她验证过的**行为层机制**全部值得抄。

## 二、可搬菜单（兔兔勾选）

### A. 自由发言三档（★推荐先做，体验差别最大）
- 现状：我们永远是「选人循环」，等于她的自由发言档但**没有沉默权**——被选中就必须说。
- 搬：设置里加三档 **仅@ / @接力 / 自由发言**；自由档下每个成员**可以选择不说**
  （她的 observe/pass 语义），沉默无痕不插消息。
- 我方成本：GroupChatScheduler 加「门控」回合（V4 曾有、V5 为省钱砍掉）——
  折中：选人 prompt 里允许返回「无」已有，补的是**被选中者自己可以 pass**。

### B. Owner 抢权（★小刀高收益）
- 现状：`groupInterjectionPending` 只重置发言预算，**正在排队的角色还是会说**。
- 搬：兔兔一发言 → 未开口的全部作废（正在生成的让它说完），围绕新消息重选。

### C. 链深闸 / 发言上限语义
- 现状：`maxReplies = 3` 硬编码。
- 搬：改成**链深**概念（AI 因 AI 而说 = 深度+1，兔兔说话重置为 0）+ 可调上限。

### D. 房间级最小发言间隔（滑块）
- 她的 `min_speak_interval_ms`：房间刚有 AI 说过话，间隔内不许再自动开口；
  兔兔直接 @ 的豁免。治「三个角色瞬间刷屏」。

### E. @ 接力（AI 也能 @ 人）
- 现状：只认**兔兔消息里**的 @；AI 回复里的 @ 一跳即断（selectNextSpeaker 只看 history.last）。
- 搬：AI 回复里的 @ 也能唤起下一个（受链深闸约束）。

### F. 服务端化（大活，以后再说）
把房间/消息搬进 hub 拿 seq + 断线补齐 + 后台继续跑。工程量 = 她 860 行 plan 的规模，
不建议现在做；等 V5 行为层打磨到位、兔兔真的需要「关掉 App 群聊继续」时再立项。

## 三、建议顺序
B（抢权，最小刀）→ A（三档 + 沉默权）→ E（@接力）→ C/D（节奏调参）→ F（另立项）
