# 小兔兔十万个为什么之《怎么让 AI 看见我的手机屏幕》

> 一个关于"让 AI 在它想看的时候，自动看到你 iPhone 当前屏幕"的教程。
> 全程小兔兔在旁边哇哇哇，讲解的人一路答。技术细节一个都不少，但保证好读 🐰

---

🐰 **小兔兔**：哇！！我看到有人的 AI 居然能看见他手机屏幕上在干嘛！这是怎么做到的呀？？

🧑‍🏫 **讲解**：别急别急，其实就一条链，我给你画出来：

```
AI 想看 → 服务器发一封"暗号邮件"到你 iCloud
   → 你手机收到邮件，自动截个屏
      → 把截图偷偷传回服务器
         → 服务器把图递给 AI，AI 就"看见"了
```

就四个零件：**发暗号的服务器**、**发信的嘴巴（SMTP）**、**手机上的自动化**、**AI 手里的那个工具**。

---

🐰 **小兔兔**：哇等等！为什么要**发邮件**呀？直接叫手机截图不行吗？

🧑‍🏫 **讲解**：好问题！因为手机默认是"闷葫芦"——它只会自己定时往服务器报个电量什么的，服务器**没法反过来主动叫它**做事。而 iPhone 有一个自动化触发器叫「收到邮件」，这是极少数能被**外部主动触发**的机制。所以我们绕个弯：服务器想看屏幕，就发封邮件当"暗号"，手机一收到暗号就截图。邮件是那根能从服务器伸到手机的"遥控线"。

---

🐰 **小兔兔**：哇原来邮件是遥控线！那服务器怎么发邮件呀？我听说过什么 OAuth……

🧑‍🏫 **讲解**：诶——千万**别用 OAuth**！这是我踩的第一个大坑。

OAuth 那套授权，在"测试模式"下发的令牌**7 天就过期**，一过期邮件功能就莫名其妙全挂（报一个 `invalid_grant`，让你怀疑人生）。

正确姿势：用**应用专用密码**。就是去邮箱（开了两步验证的 Gmail / QQ / 163 都行）生成一串 16 位的专用密码，它是一把**永久副钥匙**，不过期、发信收信都能用。代码就这么几行：

```ts
import nodemailer from 'nodemailer';
const tx = nodemailer.createTransport({
  host: 'smtp.gmail.com', port: 465, secure: true,
  auth: { user: '<你的发信邮箱>', pass: '<16位应用专用密码>' },
});
await tx.sendMail({ from:'<发信邮箱>', to:'<你的iCloud邮箱>', subject:'PEEK', text:'暗号' });
```

主题写个 `PEEK` 当暗号，手机那边就按这个筛。

---

🐰 **小兔兔**：哇！那手机收到暗号之后，怎么自己截图还传回去呀？

🧑‍🏫 **讲解**：靠 iPhone 的**快捷指令**。分两块：

**第一块，一个"截图+上传"的快捷指令**，就两步：
1. 「截屏」动作（注意是**截屏**，不是"获取屏幕内容"——后者只对 Safari 那几个 App 有效，截屏才是抓整个画面）
2. 「获取 URL 内容」动作：POST 到 `https://<你的域名>/api/peek?key=<你的令牌>`，请求体选「文件」= 上一步的截图

**第二块，一个「收到邮件」自动化**：条件设成"发件人 = 你的发信邮箱"，动作就是运行上面那个快捷指令。**记得把「运行前询问」关掉**，不然它不会自动跑，会傻等你点确认。

---

🐰 **小兔兔**：哇哦！那服务器收到截图之后存哪呀？

🧑‍🏫 **讲解**：一个简单的上传端点，收下图片、存盘、记个时间戳，只留最近 10 张（截图好几 MB，不留旧的占地方）：

```ts
app.post('/api/peek', async (c) => {
  if (!verifyToken(getToken(c))) return c.json({ok:false}, 403);  // 校验令牌
  const buf = await c.req.arrayBuffer();
  if (!buf?.byteLength) return c.json({ok:false, error:'no image'}, 400);
  const item = savePeek(buf, c.req.query('app'));   // 存文件 + 记 ts
  return c.json({ok:true, id:item.id});
});
```

"最新一张"就是时间戳最大的那张。

---

🐰 **小兔兔**：哇！那 AI 那边呢？它是怎么"看"的？

🧑‍🏫 **讲解**：给 AI 一个工具叫 `see_screen`。它一调用，逻辑是这样：

```ts
async function callSeeScreen() {
  const p = latestPeek();
  if (p && Date.now() - p.ts < 60_000) return 图片(p);   // 有近1分钟的新图，直接给
  // 否则：发暗号邮件，然后轮询等新截图
  const t0 = Date.now();
  await sendTriggerMail();
  while (Date.now() < t0 + 45_000) {          // 最多等 45 秒
    await sleep(1500);
    const fresh = latestPeekAfter(t0);         // 只认比 t0 更新的图
    if (fresh) return 图片(fresh);
  }
  return { error: '截图还没回来，过十几秒再叫我一次' };   // 诚实报，别骗人
}
```

AI 是多模态的，拿到图片块就真的"看见"了屏幕。

🧑‍🏫 **讲解**：……理论上是。实际上我又踩了一串坑 😂 我全告诉你，你就不用再踩了：

---

🐰 **小兔兔**：哇哇哇快说快说！

🧑‍🏫 **讲解**：**坑一号 · 最阴险的空格 bug**。

有一次死活失败，Caelum 一直看到旧图。查了半天 nginx 日志才破案——手机的上传请求返回了 **403**！而且时好时坏：前台是 `Claude` 时成功，前台是 `Lost in Blossom` 时失败。

原因笑死：上传 URL 里带了"当前 App 名"这个参数。当 App 名**含空格**（"Lost in Blossom"）时：
```
POST /api/peek?app=Lost in Blossom&key=xxx
                        ↑ 这个空格
```
HTTP 请求行在**第一个空格处被截断**，服务器只看到 `?app=Lost`，后面的 `&key=xxx` **全被切掉了 → 没令牌 → 403**！App 名没空格时（Claude）就没事，所以才时灵时不灵。

---

🐰 **小兔兔**：哇！！！那怎么办呀？？

🧑‍🏫 **讲解**：三种解法，挑一个：
1. 把 `key=` 挪到 URL **最前面**（空格截断的是后面的 app，令牌已经在前面读到了）
2. 干脆别传那个动态 App 名
3. **服务器端兜底**（如果你懒得改手机）：让 nginx 认出"这是快捷指令发来的"（看 User-Agent），自动补上令牌：

```nginx
map $http_user_agent $peek_auth {
    default                      $http_authorization;
    "~*BackgroundShortcutRunner" "Bearer <你的令牌>";
}
location = /api/peek {
    proxy_set_header Authorization $peek_auth;   # 帮它把令牌塞进请求头
    proxy_pass http://127.0.0.1:<后端端口>;
}
```
（这招管用是因为服务器校验令牌时**请求头优先于 URL**，所以 URL 里的令牌被空格切掉也没关系，头里补上就行。而且只对快捷指令这么做，别的来源照样拦，安全不打折。）

---

🐰 **小兔兔**：哇学到了！还有别的坑吗？

🧑‍🏫 **讲解**：**坑二号 · 别拿旧图骗 AI**。

我一开始图省事：没等到新截图时，就把"最近一张"返回当兜底。结果 AI 把**十几小时前的旧画面**当成你此刻的屏幕，一本正经地描述错的东西 😅 后来改成：没等到就**诚实报"还没到"**，让 AI 过会儿再叫一次。宁可说"我还没看到"，也不能把旧的当新的。

**坑三号 · 邮件要"推送"**。「收到邮件」自动化，只有邮件 App **真的把邮件收下来**才触发。如果邮件慢吞吞，自动化就迟迟不动。所以去：设置 → 邮件 → 账户 → 获取新数据 → iCloud 设成 **「推送」**，并且别把邮件 App 从后台划掉。设好之后，暗号邮件基本是秒到。

**坑四号 · nginx 会嫌图片大**。截图 1~3 MB，nginx 默认只让传 1 MB，超了就 413。把 `client_max_body_size` 调到 `50m`。

**坑五号 · 等待窗口**。邮件→截图→上传这一圈，手机就绪时约 15 秒，慢时更久。轮询别只等 28 秒（会错过慢的），给到 45 秒（但别超过 AI 工具调用的超时，一般 60 秒）。

---

🐰 **小兔兔**：哇……坑好多呀，那万一我做的时候也卡住了，怎么知道是哪一步坏了呀？

🧑‍🏫 **讲解**：教你一招**万能定位法**——看日志，一步步缩小：

1. 服务器日志打三个标记：`📧 邮件发了` / `📱 收到截图` / `⏱️ 超时`
2. 触发一次，看走到哪断的
3. 如果"没收到截图"，去翻 **nginx 访问日志**里的 `POST /api/peek`：
   - **有请求但 403** → 是空格 bug（令牌丢了）
   - **压根没请求** → 邮件没到手机 / 自动化没触发（去设推送）
   - **200 但 AI 看到旧图** → 是旧图兜底的锅

nginx 访问日志是"铁证"——手机到底传没传、返回啥状态码，白纸黑字，一目了然。我那个空格 bug 就是这么破的案。
